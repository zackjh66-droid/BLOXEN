# Reproduce the experimental package

The public source contains the original Hollowwake runtime, UI, import metadata and build scripts. It contains no Fortnite binaries, PAK archives, private signing keys, account database or backend secrets. The official public Season6 promotional background is included under conditional fan-content terms; see VISUALS.md. This is unfinished compatibility software, not a working game port.

The supplied signed package needs no compilation on the player's computer. These instructions describe the authorized hosted Windows build used to create it.

1. Use a standard GitHub Actions `windows-2022` runner with Visual Studio 2022, C++ Universal Windows Platform tools, Windows SDK 10.0.19041.0 and UWP/.NET Native tools. Standard runners on a public repository were used; no larger/paid runner or private SDK was provisioned. Review current service allowances before starting your own workflow.
2. Retain `hollowwake/experimental-0.4.6` and `hollowwake/client-runtime` as sibling source directories. Run `hollowwake/experimental-0.4.6/Build.ps1 -OutputDirectory <artifact-directory>` in Windows PowerShell. The included `workflow.yml` is the manual, boolean-gated workflow used here; its checkout/upload action revisions are pinned.
3. NuGet restore uses the official Microsoft UWP dependencies declared by the C# project. Native code compiles against Windows Store API-family headers and `windowsapp.lib`. No archive-supplied compiler, launcher, dependency installer, XDK/GDK or leaked source is used.
4. The build creates a non-exportable development-signing key in the disposable runner's certificate store and exports only its public CER. It compiles native runtime and distinct compiler-managed TLS donor DLLs, runs original mapped-TLS fixtures, a negative SHA256 test and the actual production dependency resolver against original forwarder/target fixtures, builds/signs x64 APPX, and verifies its signature with the public certificate temporarily trusted on that runner.
5. `Test.ps1` installs/activates the real UWP package on hosted Windows, checks executable-memory/TLS/window/graphics/system-information contracts and all six menu buttons without scrolling, verifies a real missing-API fail-fast call and process exit, checks startup log recovery, then runs the package's own account-linking/restart/logout/revocation flow against the existing Hollowwake service. Test accounts are separate from existing users. Fortnite is neither downloaded nor executed by this workflow. A successful hosted build does not establish Xbox compatibility.
6. Collect APPX, `Dependencies/x64`, public CER and safe text/JSON logs. Do not export the private key, UWP protected session files, browser cookies or account secrets. Each rebuild has a new certificate; the delivered CER applies to the delivered APPX. Certificate expiry is visible in the CER.

Private client inputs are imported directly onto the tester's console after installation, with pinned hashes. See INSTALL.md. The initial 131-file import does not include the content needed for a lobby. The optional full import is separate and much larger.

The preserved website/backend sources and prior migrations are included in the full source archive. Website routes and styling have been redesigned; the existing authentication service, account database and adapter behavior are preserved. No new backend migration or secret rotation is required to install this separate package. The client-compatible adapter remains a prototype disabled in production; project-account login does not imply native Fortnite login.
