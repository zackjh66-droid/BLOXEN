# Hollowwake 0.4.1 client boot experiment — Xbox testing

This is an experimental compatibility runtime, not a functioning Fortnite port. No lobby/character/locker/shop success or Xbox success is claimed. Original game files are NOT in this download. The package can import the pinned archive, map the real executable/dependencies, initialize original modules and attempt main entry. Missing APIs fail fast with a named text log. An early app closure is expected; it is not a successful lobby boot.

1. Keep your working companion installed. If you already installed Client Experiment 0.4.0.0, deploy this as an UPDATE to the same identity; do not uninstall it. The 0.4.1.0 update is intended to preserve its account link and imported boot files. Update preservation has not yet been verified on Xbox. If Portal rejects the update, send its exact error rather than uninstalling. This package has a separate identity, `Hollowwake.ClientExperiment`. Extract the download ZIP using your phone/tablet's normal file manager; no compilation or PC software is required.
2. Open the Xbox Device Portal address shown in Dev Home. Use Apps/Add or Deploy, choose `Hollowwake_0.4.1.0_x64.appx`, then add ALL supplied `Dependencies/x64/*.appx`. Finish installation. The public `HollowwakeExperiment.cer` matches this development-signed package; no private key is distributed. Do not disable signature validation. Device Portal normally handles development-package sideloading without a separate certificate-import step; if it rejects the publisher, send the exact HRESULT. Portal's HTTPS server-certificate settings are separate from application signing.
3. In Dev Home, highlight **Hollowwake Client Experiment**, press **View**, select **View details**, change **App type** to **Game**, confirm with **A**, then **B** and relaunch. This document-verified procedure is illustrated by Microsoft DirectX maintainer Chuck Walbourn: https://walbourn.github.io/directx-and-uwp-on-xbox-one/ . Game mode is recommended for the client's memory demands; it is not proven mandatory for linking or initial policy checks. It increases a compatible UWP app's resource allocation; it does not implement missing desktop APIs. Labels can vary by console OS.
4. Link using your EXISTING Hollowwake website account and explicitly approve this new device session. The experiment has isolated storage, so it cannot silently reuse the companion's protected token. Later launches restore its own protected session. Never enter Epic credentials.
5. Choose **Show launch log** first. Return `runtime-policy.txt` or a screenshot BEFORE downloading game files. Successful memory, packaged TLS-slot, window/message and graphics contracts report 621. If a native startup crashes, the next launch skips those checks so the managed log viewer stays accessible. In that viewer, choose Allow native checks next launch and restart only when you want to retry. Controller count is an observation, not a controller-in-game test. A negative HRESULT or failed contract stops import. These checks exercise the runtime's actual API path; they are not Fortnite rendering.
6. If you already completed Import boot files in 0.4.0.0, do not download again: after updating, restart and choose Attempt client boot. Otherwise, for the first real-client initialization test, choose **Import boot files**. This fetches 131 pinned files directly from byte ranges of the original source: 135,482,923 compressed bytes, 249,412,544 extracted bytes. Allow 2 GB reported free app storage. Every file is SHA256-verified against the inspected input; the full ZIP is NOT downloaded/authenticated in this mode. Compressed partial files are retained for retry. This includes the actual executable and x64 DLLs, plus the supplied Season 6 splash artwork. It excludes launchers/scripts and full PAK/media assets; it is insufficient for a lobby.

   **Import full archive** is separate, for later asset-level testing. It downloads the original listed source directly to the console, not through a Hollowwake mirror: https://public-build-archives-bucket.erafn.dev/6.21.zip . Download 12,528,679,454 bytes; SHA256 bae66d8b0ff7e8ebea4361e835579c180bc2a2e618d04808f72b40214ababee5. Expanded files total 26,771,777,271 bytes. Allow about 40 GB plus overhead in Xbox development storage. The app checks reported free space; actual partition quotas/write failures may differ. If needed, adjust development storage using the console's own settings. No paid storage or computer is required. Do not download the full archive merely to reproduce an already named missing API.

If the archive host refuses ranges on your console, stop and send the HTTP error. Do not download all game assets merely to retry an identified missing API. A separate full-archive fallback is available: download the original ZIP unchanged using a browser, upload it into this experimental package’s LocalState as `Original-6.21.zip` using Device Portal, then choose **Import full archive**. The app verifies the exact length and SHA256 before extraction. This fallback needs the large storage described above; Xbox Portal/browser upload limits are unverified. Do not upload game files to Hollowwake’s public repository or website.

7. Keep the app foreground during import. Suspending/exiting retains downloaded bytes; retry resumes exact HTTPS byte ranges. It verifies the entire ZIP before extraction, checks paths/links/expanded sizes/nested archives, and writes a separate GameClean copy. The original ZIP remains unchanged. Exactly the three previously identified additions are moved to GameQuarantine: custom FortniteLauncher.exe, Launcher.bat and imgui.ini. Other files are not removed merely for being unsigned. Nothing in the archive is installed as a driver or run as a launcher/script. `import-inventory.txt` records every copy/quarantine and SHA256. This is not a claim of a pristine Epic distribution.
8. Choose **Attempt client boot**. The app verifies the original main executable SHA256 and allowlisted DLL hashes, maps/relocates images, sets TLS slots, resolves supported imports, registers x64 unwind tables and attempts original dependency initialization/main entry. A called unimplemented API logs `CALLED_UNSUPPORTED <DLL>!<symbol> caller=<module/RVA>` and terminates the experiment. Structural/hash/policy failures can stop earlier without guest entry. No success values are fabricated for missing APIs. Reopen the app after a closure.
9. Select **Show launch log**, or use Device Portal's app file explorer to download this package's **LocalState/native-launch.log**, **runtime-policy.txt**, **managed-launch.log**, and, if import failed, **import-inventory.txt** or **boot-import-inventory.txt**. Some Portal versions place package data under LocalAppData rather than a package selector. The in-app log viewer is the fallback. Send only text logs/screenshots; do not upload protected session files, memory dumps, credentials or the game archive.

Report console model/OS, App versus Game classification, policy results, whether linking survives restart, and the last EXECUTE/STOP/CRASH/CALLED_UNSUPPORTED line. If original loading/lobby pixels appear, send a screenshot and steps; do not infer success from the host's imported splash background. The full lobby, persistent game profile and shop integration remain unfinished. Matchmaking has no server and remains unavailable.
