# Linked accounts — 0.5.7

Launcher linking preserves the existing Hollowwake device session. Immediately before native entry the launcher requests `/api/client-adapter/exchange` with that session, validates the exact build/origin/account ID, then passes only a 300-second single-use game ticket to `HWConfigureClientLogin`. The native launcher constructs the exact build's `AUTH_TYPE=exchangecode` arguments through its guest command-line/WinMain bridge. No project session, password or game refresh token is embedded in the MSIX or passed as an OS process argument.

The prepared private copy replaces 27 bounded standalone account/Fortnite service hostname literals with Hollowwake's HTTPS hostname. SHA-256 input pinning, non-executable section checks, unchanged image size and a recomputed explicit runtime pin are enforced. No instructions, original archive, CA validation or TLS verification are patched. Both `/client621/...` and native root `/account/api/...`, `/fortnite/api/...` route to the same adapter. This is a static endpoint change, not execution proof that every URL is assembled as expected.

Game account IDs persist in `client621_account` and are bound to the actual linked Hollowwake user. Display names follow that user. Access and rotating refresh credentials are separately scoped and hashed at rest; refresh cannot authorize project/device APIs. Revoking the linked device or suspending the account invalidates game authorization. Logout kills the device's game credentials. Native Basic public-client metadata never provides account authority. Password/client-credentials grants are rejected. The additive client_id migration preserves existing sessions and binds refresh grants to their original public-client identifier.

Existing profile/equipment/catalog adapters share authoritative admin inventory/shop records and reject unvalidated cosmetics. They are protocol implementations tested with owned fixtures; native client interpretation, loading, character rendering, menus and lobby operation are UNTESTED in this build. Presence is not implemented; Sites has no raw-TCP XMPP listener. Matchmaking remains disabled. No official Epic account is created or used.

Game code may write credentials to its own Saved/Logs. Those raw game logs are private and are not included in the structured diagnostic upload. Never publish raw logs or the session vault without redaction. The sanitized startup report excludes arbitrary command lines, tokens, URLs and file contents.
