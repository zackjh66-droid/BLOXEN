# ASSETS

Table `assets` (SQLite, `src/lib/db.js`): id, type id/name, name, source (archive URL), source date, provenance grade, availability, note; `asset_uses` links assets to places; `missing_asset_log` records every request for a MISSING asset; local path and SHA-256 columns exist for assets that are actually stored.

Current state: **every catalog asset is MISSING** (only metadata archived). Place-embedded asset ids (e.g. Crossroads 1, World HQ 29) are recorded as references only.

Asset service (`/asset/?id=` on the compat server): numeric ids only (400 otherwise); MISSING → 404 with body "MISSING" plus a log row; **never** proxies to Roblox and never returns a homemade substitute. Avatar wearables that are MISSING are skipped by the game server and reported (`missingAssets`), which the e2e test asserts. Body colours are data, not assets, and do reach the spawned character (asserted).

No uploads are accepted anywhere (removes the malicious-upload surface).

**Adding a real archived asset** (path now implemented, UNIT/INTEGRATION-TESTED in `tests/assets.test.js`): `node tools/register_asset.js <file> --id N --type <AssetTypeId> --name .. --source <https-url|repo@commit:path> --date YYYY-MM-DD --grade <PRESERVED|ARCHIVED-EXACT|ARCHIVED-NEAR-DATE|RECONSTRUCTED-FROM-EVIDENCE>`. It refuses missing/invalid provenance (INFERRED/UNKNOWN content grades are not accepted), hashes the file, copies it read-only by SHA-256 into the asset directory (`data/assets`, git-ignored; `BLOXEN_ASSETS` overrides) and records it in `preservation/manifests/assets.json` (committed: hash, source, date, grade, size). At seed time a row becomes `AVAILABLE` only if the stored bytes still hash to the recorded value; `/asset/?id=` re-hashes on every serve and answers 404 + log if the file is absent or was changed. Files are addressed only by 64-hex hash, so no request can name a path. **The committed manifest is empty**: no real asset content has been retrieved yet (the sources that might hold some, such as the archive.org client collection's `Places.7z`/`Models.7z` and its 3.5 GB main archive, are multi-GB and unexamined; the collection description says RobloxPlayer clients from 2015 are not in it).
